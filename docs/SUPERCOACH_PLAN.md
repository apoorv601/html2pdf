# Plan: "SuperCoach" — AI Personal Fitness & Life Coach App

## Context

The user wants to build an AI-powered personal fitness/life coach app that behaves
like a real human trainer rather than a passive logging tool. The defining
difference from ordinary fitness apps is **proactivity + intelligence**: the app
initiates contact (morning/afternoon/evening), *demands* food and exercise logs,
understands free-form input (photo, voice, or text), auto-calculates calories,
adapts a coaching plan over time, and responds to the user's psychology (e.g.
encouragement when frustrated). It should feel like a "super coach."

Key facts established:
- **AI brain:** Google **Gemini 3.5 Flash** (via Google AI Studio for prototyping,
  Vertex AI for production). Flash is fast, cheap, and multimodal (handles meal
  photos + text), which fits this use case well.
- **Platform (decided):** **Flutter** mobile app (single codebase, iOS + Android,
  strong native push/camera/mic support).
- **Backend (decided):** **Firebase** — Auth, Firestore, Cloud Storage, Cloud
  Functions, and FCM push, which pairs naturally with Gemini/Vertex AI.
- **Voice (decided for v1):** voice-to-text logging (speak → transcribe → Gemini
  parses). Full conversational voice coach is a later phase.
- **Scope (decided):** capture the full vision but phase it MVP → V2 → V3.

## 1. Product Vision & Core Principles

1. **Proactive, not passive** — the coach reaches out on a schedule and chases
   missing logs instead of waiting for the user.
2. **Frictionless logging** — photo, voice, or text; the AI does the calorie math
   and structuring. Logging a meal should take seconds.
3. **Adaptive coaching** — onboarding interview builds a personalized plan;
   the plan adjusts as data accumulates and pushes the user *gradually* harder.
4. **Emotionally intelligent** — detects frustration/slips and responds with
   empathy + motivation, not guilt.
5. **Transparent dashboard** — clear daily/weekly views of calories in/out,
   exercise, streaks, and progress toward goals.

## 2. Feature Brainstorm (full vision)

### A. Nutrition / Food Intake
- Scheduled meal prompts (breakfast/lunch/dinner/snacks) with smart timing.
- **Multimodal logging:** snap a photo, speak it, or type it.
- Gemini Vision estimates dish, portion, and calories + macros (protein/carbs/fat).
- Confirmation step: AI shows its estimate, user can correct ("it was 2 rotis").
- Auto-aggregated daily calorie + macro totals vs. target.
- "You haven't logged lunch" nudges if a meal window passes with no entry.
- Water intake tracking; hydration reminders.
- Pattern insights ("you tend to over-eat on weekends").
- Optional barcode scan / food database fallback for packaged items.

### B. Exercise / Activity
- Onboarding captures preferred workout days/times, fitness level, constraints
  (injuries, equipment, home/gym).
- Personalized workout plan generated by Gemini; adapts weekly.
- Scheduled workout reminders; post-workout check-in ("did you do it?").
- Log exercises via voice/text ("ran 3km, 25 min") → estimated calories burned.
- Optional integration with phone health data (Apple Health / Google Fit /
  Health Connect) for steps, heart rate, workouts.
- Streaks, progressive overload suggestions, rest-day logic.

### C. The AI Coach (conversational layer)
- **Onboarding interview:** coach-style chat to learn goals (lose fat, gain
  muscle, stay fit), current status, lifestyle, preferences, schedule.
- Daily check-ins and a persistent chat thread with memory of history.
- **Accountability engine:** detects missed logs/workouts and escalates nudges
  (gentle → firmer), but stays supportive.
- **Emotional intelligence:** sentiment detection; if user is frustrated or
  slipping, switch to empathetic/motivational mode and adjust expectations.
- Weekly review: summarizes the week, celebrates wins, sets next week's micro-goals.
- "Gradual push" logic: small, compounding increases rather than big jumps.

### D. Dashboard & Insights
- Today view: calories in/out ring, macros, meals logged, workout status, water.
- Trends: weight, calories, adherence %, streaks over time (charts).
- Goal progress (target weight / fitness milestones).
- Achievements/badges for motivation.

### E. Notifications / Engagement
- FCM push for meal prompts, workout reminders, missed-log nudges, weekly review.
- Smart timing based on user's logged routine + quiet hours.
- Snooze / "log now" quick actions from the notification.

### F. Profile & Settings
- Goals, body metrics, dietary preferences/restrictions, schedule, quiet hours,
  notification preferences, units, data export.

## 3. Phased Roadmap

### Phase 1 — MVP ("Log + Nudge")
Goal: prove the core loop — proactive prompts → effortless logging → dashboard.
- Firebase Auth (email + Google sign-in).
- Onboarding interview (chat with Gemini) → stores goals & schedule.
- Food logging via **photo, voice-to-text, and text**; Gemini parses → calories+macros.
- Confirmation/correction step before saving.
- Manual exercise logging (voice/text).
- Today dashboard (calorie ring, meals, macros, workout status).
- Scheduled push notifications (meal prompts, workout reminder) + missed-log nudge.
- Persistent coach chat thread.

### Phase 2 — "Adaptive Coach"
- Auto-generated, weekly-adapting workout & nutrition plans.
- Accountability escalation + emotional/sentiment-aware responses.
- Weekly review summaries.
- Trends/charts, streaks, achievements.
- Health Connect / Apple Health / Google Fit integration (steps, workouts).
- Water tracking, hydration reminders.
- Smarter notification timing.

### Phase 3 — "Super Coach"
- Full **conversational voice coach** (STT ↔ Gemini ↔ TTS).
- Deep pattern insights & predictive nudges.
- Barcode/food-database lookup, recipe suggestions, meal planning.
- Optional web dashboard companion.
- Advanced personalization & long-term periodization.

## 4. Technical Architecture

```
┌─────────────────────────────┐
│      Flutter Mobile App      │  iOS + Android
│  UI · chat · camera · mic    │
│  state mgmt (Riverpod)       │
└───────────────┬──────────────┘
                │  HTTPS / Firebase SDK
┌───────────────▼──────────────────────────────┐
│                  Firebase                      │
│  Auth · Firestore · Cloud Storage (photos)    │
│  Cloud Functions · FCM push · Scheduler        │
└───────────────┬──────────────────────────────┘
                │  server-side calls (keys hidden)
┌───────────────▼──────────────┐
│   Gemini 3.5 Flash (Vertex)   │  vision + chat + parsing
│   STT / TTS (Phase 3)         │
└───────────────────────────────┘
```

**Key principle:** all Gemini API calls go through **Cloud Functions**, never
directly from the app — this keeps API keys secret, lets you control cost,
add caching, and centralize prompt logic.

### Stack details
- **App:** Flutter + Dart, **Riverpod** for state, `go_router` for navigation.
  Key packages: `firebase_auth`, `cloud_firestore`, `firebase_storage`,
  `firebase_messaging`, `image_picker`/`camera`, `speech_to_text`, `fl_chart`.
- **Backend:** Firebase Cloud Functions (TypeScript). Use the **Vertex AI /
  Google Gen AI SDK** server-side. Cloud Scheduler + Functions to fan out
  scheduled notifications.
- **AI:** Gemini 3.5 Flash for multimodal meal estimation, plan generation,
  and chat. Structured outputs (JSON schema / function calling) so the app gets
  clean `{food, calories, protein, carbs, fat}` objects instead of prose.

### Firestore data model (collections)
- `users/{uid}` — profile, goals, body metrics, preferences, schedule, quiet hours.
- `users/{uid}/meals/{mealId}` — timestamp, type, raw input, photo URL, AI estimate,
  user-corrected values, calories, macros.
- `users/{uid}/workouts/{workoutId}` — timestamp, type, duration, calories burned,
  source (manual/health).
- `users/{uid}/plans/{planId}` — current nutrition + workout plan, version, active range.
- `users/{uid}/chat/{messageId}` — coach conversation history (for context/memory).
- `users/{uid}/dailyStats/{yyyy-mm-dd}` — rolled-up totals for fast dashboard reads.
- `users/{uid}/notifications/{id}` — schedule + delivery log.

### Notification pipeline
- Cloud Scheduler triggers a Function on intervals (e.g. hourly).
- Function checks each user's schedule/quiet hours + what's logged today, decides
  who needs a meal prompt / workout reminder / missed-log nudge, sends via FCM.
- Quick actions in the notification deep-link into the log screen.

### AI prompt design (notes for implementer)
- System persona prompt = "SuperCoach": supportive, accountable, gradually pushes.
- **Meal estimation:** send image (+ optional text) → request strict JSON schema
  output for food items, portions, calories, macros, confidence.
- **Chat/coaching:** include recent profile + recent stats + recent chat as context;
  include a sentiment/empathy instruction so tone adapts to frustration.
- **Plan generation:** structured JSON plan (days, exercises, sets, targets) so the
  app can render and schedule it.
- Cache/limit calls; prefer Flash for cost; consider Gemini Pro only for heavy
  weekly-review reasoning if needed.

## 5. Security, Privacy & Cost
- API keys only in Cloud Functions / Secret Manager — never in the app bundle.
- Firestore Security Rules: each user can read/write only their own `users/{uid}/**`.
- Health & food data is sensitive personal data — add a clear privacy policy,
  consent on onboarding, and a data-export/delete option.
- Cost control: Gemini Flash for everything by default; compress images before
  upload; batch/limit scheduled calls; set Firebase budget alerts.

## 7. Verification (how to confirm it works end-to-end)
Since this is greenfield, verification is per-phase against the MVP loop:
1. **Auth:** sign up / sign in; user doc created in Firestore.
2. **Onboarding:** complete the coach interview; goals + schedule persisted in `users/{uid}`.
3. **Food log (photo):** snap a meal → Gemini returns calories/macros → confirm/correct → saved → dashboard ring updates.
4. **Food log (voice/text):** speak/type "two eggs and toast" → parsed → saved.
5. **Exercise log:** "ran 3km" → estimated burn → workout status updates.
6. **Notifications:** simulate a meal window passing with no log → missed-log push arrives → tapping deep-links to log screen.
7. **Chat:** send a message to the coach → context-aware, supportive reply; history persists.
8. **Dashboard:** daily totals reflect all logged items; trends populate over multiple days.
Tooling: Firebase Emulator Suite (Auth/Firestore/Functions) for local testing;
Flutter integration tests for the log → save → dashboard flow; manual device test
for camera, mic, and push notifications.
